# 달디단 오케스트레이터

## 에이전트 팀

| 에이전트 | 역할 |
|---------|------|
| `ui-developer` | 프론트엔드 위젯·컴포넌트·페이지 구현 |
| `api-developer` | Route Handler·Supabase·외부 API 구현 |
| `qa-validator` | 통합 정합성 검증 |

---

## 실행 흐름

### Phase 1: 요청 분석
- **UI 전용**: 위젯·컴포넌트 스타일 수정 → ui-developer만 투입
- **API 전용**: 엔드포인트 추가·쿼리 수정 → api-developer만 투입
- **풀스택**: 새 기능 → 두 에이전트 병렬 투입
- 수정 대상 파일 경로 확정, API 타입 의존성 파악

### Phase 2: 작업 명세 작성
각 에이전트에게 전달할 명세:
- ui-developer: 구현 대상, 기능 요구사항, accent 색상, API 스펙(타입 포함)
- api-developer: 엔드포인트, 요청 파라미터, 응답 타입, 외부 API 여부
- qa-validator: 검증 대상 파일, 경계면 체크포인트

### Phase 3: 에이전트 실행
풀스택 시: api-developer가 타입 스펙 먼저 확정 → 양쪽 병렬 구현

### Phase 4: QA 검증
`qa-validator` 실행 → 오류 있으면 해당 에이전트 수정 요청 → 재검증

### Phase 5: 최종 처리
1. `npx tsc --noEmit` 최종 확인
2. `npm run lint` 확인
3. **자동 push** — 위 검증(타입·lint)이 모두 통과하면 사용자 확인 없이 자동으로 진행:
   - `git add -A`
   - 변경 내용을 요약한 한글 커밋 메시지로 `git commit`
   - `git push`
   - ⚠️ 검증 실패(타입 오류·lint 오류·빌드 실패) 시 push 금지 — 오류 수정 후 재검증
4. 완료 요약: 구현 파일 목록, 주요 변경사항, 푸시 결과(커밋 해시)

## 에러 핸들링

| 상황 | 처리 |
|------|------|
| 외부 API 키 없음 | 즉시 보고, 환경 변수 설정 안내 |
| 타입 빌드 오류 | qa-validator 보고 → 해당 에이전트 수정 → 재빌드 |
| QA 2회 실패 | 사용자에게 직접 확인 요청 |
